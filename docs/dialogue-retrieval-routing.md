# Поиск темы при нераспознанной фразе — 23 октября 2026

Рабочая версия поведения: `mvp-feedback/20261023-v3`. Авторский пакет и юридическая категория остаются прежними. Папка `dialogue-generator/output/pps/20261022-v1` — исторический подготовительный снимок, а не активный словарь фраз. Активная конфигурация: `services/category-runtime/service/conversation/policy/pps.v2.json`; извлечение: `extract.mjs`; управление разговором: `service.mjs`; предложения тем: `routing.mjs`.

## Что исправлено

Ранее при отсутствии точного распознавания поиск выполнялся, но его результаты сохранялись только для диагностики. Затем всегда выдавалось сообщение о неподобранном ответе. Теперь кандидаты участвуют в уточнении темы.

Порядок работы:

1. Явные пользовательские факты и текущий вопрос разбираются существующими правилами. Они имеют приоритет перед результатами поиска.
2. Если тема не определена, поиск запрашивает до 32 кандидатов по всей PPS без жёсткой фиксации прежнего stage. Проверяются SHA категории, category/stage/variant ID и допустимый числовой score; кандидаты объединяются по темам.
3. Если неясно, кто участвует, сначала задаётся вопрос о сотруднике полиции. Затем тема подтверждается вопросом Да/Нет/Не знаю. Используется общий бюджет два на раунд.
4. После подтверждения берётся совместимый вход темы с минимально известными обстоятельствами. Найденный поиском variant_id не переносит свой context в диалог. Ответы на уточнения могут подтверждать только содержание конкретного вопроса. Например, подтверждение физической силы относится к прежнему `force_actually_used`; подтверждение улицы не означает запрет уйти.
5. Если кандидатов нет либо не удалось уточнить ситуацию, доступно честное сообщение и добровольная отправка всей переписки. При технической ошибке поиска сообщается о временной недоступности, а не об отсутствии покрытия.

Новые context, NEXT исходной категории, DOCUMENT, юридические тексты и Qdrant не менялись.

## Контекст и повторения

Короткое зависимое продолжение («Говорит непонятно») дополняется последними пользовательскими сообщениями текущего эпизода. Текст помощника в запрос не попадает. Явное сообщение о новой теме ищется отдельно от старой темы, поэтому прежняя история не перетягивает поиск на себя. Старые факты сохраняются в своём эпизоде и области. Подсказка статьи не считается подтверждённой пользователем темой.

Повтор того же запроса не открывает новый бюджет и не повторяет поиск бесконечно. Подтверждения обрабатываются по nonce/revision/questionId и применяются ровно к одному текущему вопросу. Прямое сообщение о применении силы прерывает старое предположение поиска.

## Почему нельзя просто показать верхний результат

Фактический поиск bge-m3 по фразе «Меня остановил сотрудник» возвращал доставление в отдел с score около 0.671, а остановку на улице — около 0.640. Оба результата похожи по словам; первый не доказывает поездку в отдел. Новая логика учитывает явную подсказку об остановке при близких оценках и подтверждает тему у человека.

Порог 0.60 и окно близости 0.08 — инженерные фильтры предложений, не вероятность правильного ответа и не юридическая оценка. Они проверены на примерах текущей доработки и регрессионном корпусе, но независимый языковой holdout не проводился. Нераспознанные нюансы по-прежнему собираются через согласованную отправку переписки.
