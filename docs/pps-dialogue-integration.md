# Подключение Dialogue Manager PPS

Подключён пакет pps-20261022-v2, категория SHA-256:
1f3d30732d4c00d77bbb5c63b715bdddfe97e5ecaed92bb764706541c2bd26af.

Исполняемая конфигурация: services/category-runtime/service/conversation/policy/pps.v2.json.
Она содержит 47 определений, из них 45 разрешены для извлечения. active_resistance_present и attack_present заблокированы до определения их субъекта и границ значения.
pps.json содержит только исходные подсказки маршрутизации; extract.mjs реализует ограниченный разбор пользовательского текста. Примеры не используются как словарь ответов или исполняемые правила.

Проверенная авторская версия остаётся неизменным входом. Рабочая конфигурация собирается командой:

    node services/category-runtime/compile-dialogue-package.mjs "<папка авторского пакета>"

Сборщик проверяет все контрольные суммы авторского manifest, копирует определения и 14 дополнительных context-вопросов плюс вопрос об участнике. Синтетические примеры попадают только в testdata/pps-extraction.json.
Загрузка другой SHA категории блокируется; статья, результаты поиска и текст ассистента фактами пользователя не становятся.

## Поведение

- Факты привязаны к текущему эпизоду и предмету; unknown не заменяется false.
- Отрицание части обстоятельства не отрицает всё поле; события не стираются после завершения.
- Исходный NEXT используется первым. В интеграции22 октября все вопросы, включая уточнение участника, использовали лимит два на раунд; актуальное правило случая приведено в дополнении25 октября.
- Дополнительный вопрос появляется при известном участнике/подтеме, выполненных условиях, отсутствующем значении и безопасных целях всех трёх ветвей.
- Целевой variant_id проверяется на совместимость; учитываются другие уже известные различия помощи.
- Повторная памятка заменяется продолжением. После возврата телефона/документа или отзыва согласия история сохраняется, выдача устаревшего действия блокируется.
- Состояние переживает перезапуск. Ревизия, nonce, questionId и принадлежность чата проверяются сервером.
- Существующие сессии при обновлении политики получают новые управляющие кнопки через resume. История не удаляется.

## Проверки

Из services/category-runtime:

    npm ci --ignore-scripts
    npm test

Для полноценных проверок нужен точный JSON категории указанной SHA. На этой рабочей машине тесты используют ранее запечатанный pps.final.json. На другом хосте задайте CATEGORY_FULL_FIXTURE с путём к такому файлу.

681 синтетический пример проверяется настоящим interpretTurn по замороженным ожиданиям. Неуточнённые поля проверяются на отсутствие автоматического заполнения. Два test-only вопроса unknown для заблокированных полей не становятся вопросами runtime.
Проверяются все 42 ветви дополнительных context-вопросов, общий лимит, исходный NEXT, конфликты, исправления, новые эпизоды, история, изоляция пользователей и возобновление.
Пять старых opt-in проверок относятся к другим историческим форматам/пилотам и по умолчанию пропускаются. Новые PPS-проверки не заменяются этими пропусками.
Это dev/regression корпус. Независимого реального holdout нет; качество на всех русских формулировках не заявляется.

## Запуск

Gateway и интерфейс уже используют protocolVersion=2 в текущей локальной рабочей связке.
Общий маршрут: сайт 3000 -> Go 8094 -> Node 18110.
Go включает CONVERSATION_STATE_V2=true и APP_CONVERSATION_RUNTIME_URL.
Node использует существующие CATEGORY_INTERNAL_TOKEN, CATEGORY_DATA_DIR и CATEGORY_PORT.
Секреты и пользовательские сессии в Git не включаются.

Для обновления Node перезапустите services/category-runtime/service/server.mjs с прежними настройками.
GET /health показывает conversationPolicy и SHA ожидаемой категории.
Этот коммит содержит Node runtime, конфигурацию и проверки. Предшествующие изменения Go/интерфейса в рабочей копии не включаются автоматически.

Проверка пользователем: http://127.0.0.1:3000/chat, начать новый чат.
Например: «На меня кричит полицейский», «Не знаю», «Он меня бьёт», затем ответы на уточнения.
После перезагрузки должны сохраниться история и текущий вопрос; прежняя полная памятка не должна появиться вторично без просьбы.

Категория, исходные NEXT/ответы/документы и Qdrant этим подключением не изменяются.
Откат Node выполнять вместе с совместимым gateway/интерфейсом; v2-состояние не отдавать старому v1 engine.
Удалённый сервер этим локальным запуском не обновляется.


## Дополнение25 октября2026: продолжение одного случая

Общий бюджет относится ко всему текущему случаю: две пары по умолчанию, третья — только по явно принятому основанию для конкретного вопроса; четвёртая запрещена. В активном PPS список оснований третьего вопроса пуст. Исходный NEXT, supplemental, выбор участника/темы, конфликт и текстовое уточнение используют один счётчик. Новый раунд, факт, предмет, участник, перефразирование, перезагрузка или смена версии его не обнуляют. Новый бюджет появляется только при явно сообщённом отдельном происшествии. Считается фактически выданный вопрос при атомарном сохранении ответа; отклонённая заготовка и повтор доставки не расходуют ещё одну пару. Исчерпание вопросов не прекращает помощь по известным обстоятельствам.

Код использует private caseState и subject-scoped itemId; старые определения/compiled policy и681 expected не меняются. Подробности локальных проверок и ограничения: docs/pps-dm-continuity-report.json. Исторический отчёт22 октября сохранён. Локальные тесты не означают rollout сайта, актуальность законов или завершение категории.
